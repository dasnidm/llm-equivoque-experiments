# 백업 일시 오류 복구 준비안

기존 실행에서는 비공개 원본 업로드 중 오류가 나면 백업 스레드가 종료되고,
살아 있는 세션을 보존하면서 새 턴 전송이 대기한다. 이번 3개 대기 원본은 별도
원격 확인과 바이트 해시 검증을 거쳐 백업했지만 기존 프로세스의 백업 스레드는
다시 시작되지 않는다. 이 파일의 수정은 실행 중인 동결 코드에 적용되지 않았다.

준비된 수정은 업로드 전 정확한 Git 커밋을 로컬 ref로 보호하고, 실패 후 원격
브랜치가 이전 커밋인지 대상 커밋인지 확인한다. 이전 커밋이면 같은 대상 커밋을
재전송하고, 대상 커밋이면 다시 보내지 않고 원격 바이트를 검증한다. 다른 커밋이면
대기한다. 원본 SHA가 다른 경우에도 덮어쓰지 않는다. 스레드는 오류 상태를 표시하며
재확인하고, 확인에 성공했을 때만 백업 완료 처리와 로컬 정리를 수행한다.

로컬 모의 저장소에서 전송 전 실패와 전송 성공 후 확인 유실을 각각 시험했다.
기존 프로세스에 이 수정이 주입된 것은 아니다. `main_resume.py`는 기존
컨트롤러를 종료하지 않고 일시 정지하며 기존 42개 세션을 보류로 유지한다.
이미 완료된 시행은 건드리지 않고 아직 시작하지 않은 1차 시행만 별도 컨트롤러에서
시작한다. 기존 42개를 완료·실패로 확인하기 전에는 2차를 시작하지 않는다.
재개 구간은 별도 동결 프로필과 소스 커밋을 기록한다.
