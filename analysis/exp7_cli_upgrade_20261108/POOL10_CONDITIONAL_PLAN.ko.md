# 10병렬 추가 점검의 사전 조건

8모델 × 각 1대화, pool 8 점검은 272턴을 모두 통과했다. 전체 완료 속도는
96.12턴/분이고, 관측한 rolling 60초 최대 입장은 118회였다. 설정 상한
160회/분이 실제 도달 처리량은 아니다. 이를 모든 프로필의 최대값이라고
보지 않는다.

이후 진행 중인 **2모델/pool 8/110회·분 점검까지 오류 없이 통과한 경우에만**,
최신 안정판으로 원래 8모델 medium, pool 10, 상한 200회/분,
총 16대화(모델마다 2대화)의 새 기술점검을 추가할 수 있다.
pool과 실제 executor max_workers는 모두 10이며, per-model worker 간격은
기존 점검과 같이 1초이다. 최초 8모델 이름 순서를 두 번 반복한 배정으로
원래 실험 프롬프트·스키마·질문 순서를 그대로 사용한다.

직전 점검이 실패하면 이 추가 점검은 시작하지 않는다. 새 429나 다른 오류가
나면 추가 점검을 중단하고, 원본·pending을 보존·백업한다. STOP을 자동 해제하거나
불확실한 요청을 재전송하지 않는다. 이 점검 역시 본실험 표본에 포함하지 않는다.
