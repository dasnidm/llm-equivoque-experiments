# 새 persistent 실행 기술점검 중단 기록

실행 `equivoque-2026-11-08-exp7-persistent-v1`, `gpt-6-astra`, 기술점검 `attempt-01`은 독립 대화 4개를 각 34턴 완료한 후 현황판 heartbeat의 Git fetch에서 exit 128이 발생해 중단됐다. 완료된 4개는 각각 원본 RPC 감사가 통과했고, 동일 프로세스 및 동일 대화를 유지했다. 로컬 state에서 처리 중인 모델 요청은 확인되지 않았고, 나머지 14개 기술 대화는 시작되지 않았다. 코드는 원래 Git stderr를 보안상 기록하지 않아 오류의 구체적 원인은 확인되지 않았다.

확인 대기 중 보존된 heartbeat 커밋 `2868a9a512fa0d804eed15f6bb894baf0411b947`은 후속 원격 조회에서 원격 이력에 포함된 것으로 확인됐다. 후속 읽기 전용 fetch는 성공했지만 이것만으로 최초 실패 원인이 해결됐다고 단정할 수 없다. 보존 ref는 삭제하지 않았다. 새 현황판에 STOP과 기술점검 실패를 기록했고 자동으로 해제하지 않는다. 본실험 시행은 아직 시작하지 않았다.

기술점검 원본은 로컬 작업 디렉터리를 그대로 유지하고, 비공개 원본 저장소 브랜치 `raw/equivoque-2026-11-08-exp7-persistent-v1/gpt-6-astra`의 `calibration/attempt-01/`에 압축본과 manifest를 올린 후 원격 해시를 확인했다. 원격 백업 확인 커밋은 `d5a33989a925d16bac4d5cef00b619d3186ef774`이다. 기존 실행의 이 VM 미완료 작업 `model-04-job-0021` 역시 기존 원본을 그대로 둔 채 비공개 원본 저장소의 기존 실행 브랜치 아래 `transition-preservation/model-04-job-0021/`에 별도 백업하고 확인했다. 다른 VM에 있는 기존 미완료 작업은 해당 VM에 접근할 수 없어 로컬 보존과 백업 여부를 확인하지 못했다.

중단된 점검을 계속하려면 기존 네 대화를 재전송하지 않는지, 기존 evidence와 백업을 덮어쓰지 않는지, 다른 VM과 현황판이 STOP 상태를 준수하는지 확인해야 한다. 실패·불확실한 시행의 임의 대체는 하지 않는다. 기술점검이 전부 통과하기 전에는 새 본실험을 시작하지 않는다.
