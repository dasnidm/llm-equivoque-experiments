# Persistent 본실험 병렬 운영 변경

사용자는 전역 예약 상한 20과 Astra의 10병렬 본실험 시작을 요청하고, 10병렬 별도 기술점검 및 다른 모델들의 점검 완료를 기다리지 않고 시작한다고 명시했다. 새 본실험 시작 전에 이 결정을 기록한다. Astra는 기존 persistent 프로필로 1병렬 기술점검 18개 대화와 612턴의 감사 및 원본 백업을 통과했다. 이 증거는 10병렬 안정성이나 실제 모델 간 응답 분포 동등성을 입증하지 않는다. 다른 모델의 기술점검 완료를 확인하지 못했다.

현황판의 전역 20은 예약 한도이지 계정 전체 요청률 제한이나 검증된 서비스 용량이 아니다. Astra의 예약과 로컬 pool은 10으로 일치시킨다. 요청 시작 간격 1초는 각 worker 내부 설정이며 여러 VM에 공통으로 적용되는 한도가 아니다. 시작 시각과 추후 운영 설정 변경·사유, 실제 동시 요청, 성공 턴/분, p95, 목록 조회 및 응답 요청 429를 기록한다. 응답 처리 여부가 불확실한 요청은 재전송하지 않고 보존하며, 실패 시행을 대체하거나 새 STOP을 자동 해제하지 않는다.

원래 연구 조건, 배정, 시드, 모델, 노력 수준, 프롬프트, 스키마, 질문 순서, freeze 및 실행 ID는 바꾸지 않는다. 실행 방식 전환 전 수집분과 새 본실험은 기존 결정대로 분리한다. 다른 모델을 어느 VM에서 실행할지는 공통 현황판의 소유권과 모델별 준비 상태를 확인한다.
