# 상한 없는 전송 + 429 재시도 처리량 탐색

2026-11-08. 사용자의 "제한 걸지 말고 단순 리트라이" 요청에 따른 별도
기술 측정이다. 이전 본실험, 기존 기술점검의 자료·프로필·STOP은 보존한다.
어느 단계도 본실험 표본에 포함하지 않는다.

## 실행 전 고정한 비교

- 한 물리 VM에서 Astra와 5.6 Sol을 반씩 배정한다. medium, cards, seq,
  en_schema의 동일한 배정 템플릿과 전체 34턴 시행을 사용한다.
- 실제 pool 10/20/40을 순서대로 측정한다. 각각 새 대화 20/20/40개를
  실행한다. 목표는 합계 80대화·2,720개의 성공 논리 턴이다.
- CLI transport 간격 0, relay logical gate 간격 0, HTTP admission 간격 0.
  고정 초당·분당 상한은 없다. FIFO는 전송 순서만 정하며 간격을 추가하지 않는다.
- 완결된 HTTP capacity 429이면 요청 바이트를 바꾸지 않고 해당 요청만
  Retry-After + 0.1~0.4초 jitter 뒤 재시도한다. 다른 요청에는 공통
  cooldown을 부과하지 않는다. Retry-After가 없으면 지수 backoff를 쓴다.
- 200 이후 불확실한 실패, quota·인증 오류는 재전송하지 않고 STOP과
  원본을 보존한다. 새 STOP을 해제하거나 실패 시행을 대체하지 않는다.
- 종료 가능한 기술 측정을 위해 단계당 물리 시도 10,000회·새 전송 30분,
  논리 요청당 20회 재시도·대기 예산 900초·timeout 1,020초를 둔다.
  이는 고정 전송 속도 상한이 아니며 도달하면 미완료 상태로 기록한다.
- CLI 0.167.0, 동일 OAuth 경로·관리 프록시·CA, persistent app-server와
  대화 유지, native 내부 request/stream 재시도 0을 유지한다.

## 평가와 한계

성공 턴/분의 분모에는 모든 재시도·대기·마지막 대화 처리 시간이 들어간다.
실제 동시 요청 수, p95 턴 지연, 429·복구 횟수, 요청 바이트 동일성,
도구 미사용과 전체 34턴 대화 감사를 기록한다. 시작 비용을 포함한 전체
구간과 공통 길이의 지속 부하 구간을 구별한다.

표본 수와 마지막 대화의 꼬리 효과가 다르므로 탐색적 비교다. 이 세 점의
최고 관측값을 계정의 절대 최대 처리량이나 모든 모델의 속도로 일반화하지
않는다. 한 VM의 두 모델 실측이며 두 물리 VM의 결과로 표현하지 않는다.

전송 구현과 실행기는 저장소 커밋·파일 해시를 profile에 남긴다.
원본 작업 경로: `/workspace/work/exp7-unpaced-retry-20261108-v1`.
닫힌 단계마다 원본을 비공개 로그 레포의 별도 브랜치에 압축·해시 검증해
보존한다. 기존 본실험 freeze를 수정하지 않는다.
