# CLI 최신판 비교 및 제한 원인 조사: 수집 전 계획

2026-11-08 사용자 요청에 따라 기존 실험 7 수집분 전체를 다음 본실험의
주 분석에서 제외한다. 실행 환경을 바꿔 처음부터 다시 수집하려는 결정이며,
개별 응답이나 성적을 보고 시행을 선별하는 결정이 아니다. 기존 자료는
버전 비교와 감사에 필요하므로 원본·동결 파일·실패 및 불확실 요청을 보존한다.
기존 수집분을 사후에 예비실험으로 이름 바꾸지 않는다.

기존 본실험의 STOP은 유지한다. 아래 비교는 표본에 포함하지 않는 별도의
기술점검이다. 새 CLI를 쓰기 위해 기존 freeze나 지원 버전 상수를 수정하지 않는다.

## 버전과 비교 조건

- 기존: `0.159.0-alpha.3`.
- 최신 안정판: 공식 GitHub release와 npm latest가 일치하는 `0.167.0`.
- 최신 시험판: npm alpha와 공식 GitHub release의 `0.169.0-alpha.3`.
- 설치는 작업별 디렉터리에서 하며 전역 바이너리·인증 파일·HOME을 변경하지 않는다.
- frozen 모델 목록, 시스템 지침, 프롬프트, 스키마, 34턴 순서와 질문을 유지한다.
- 비교 어댑터에서 허용하는 변경은 CLI 바이너리/버전 검사와 initialize의
  clientInfo.version 메타데이터뿐이다. 원본 RPC와 기존 독립 감사기를 사용한다.
- 먼저 각 버전의 로컬 실제 CLI fixture에서 34턴, 대화/프로세스 유지,
  schema on/off, 지침/도구 표면, runner·archive·backup 계약을 검사한다.
  추가로 버전 사이 모델 입력과 도구 표면의 차이를 비교한다.

## 실제 부하 비교 순서

모든 시행은 새 프로세스·새 대화이며 실패한 시행을 재실행하거나 대체하지 않는다.
기본 조건은 Astra와 5.6 Sol, medium, cards/seq/en_schema이다.
전체 계정의 논리 turn/start 입장 간격 0.75초(80/분), pool 4, 각 버전당
4개의 완전한 대화를 먼저 비교한다. 순서는 기존 → 안정판 → 시험판 →
안정판 → 기존으로 사전 지정한다. 각 실행은 독립 stage/profile을 보존한다.
초기 순서와 캐시·서버 시간대의 영향을 완전히 제거하는 실험은 아니다.

성공하면 안정판을 중심으로 100/분 및 110/분의 별도 단계를 검토한다.
기존 110/분 실패가 전체 계정 한계인지 특정 모델·경로인지 구분하기 위해
모델별 입장/실제 RPC 중첩과 오류 위치를 기록한다. 추가 모델 비교는
별도 새 stage로 명시하며 조건별 표본에 포함하지 않는다.

성공 턴/분, 전체 종료 시간, p95 응답 시간, 실제 입장 시각, 관측한 동시 RPC 수,
catalog/response 429를 구분한다. RPC는 HTTP 내부 시도 횟수가 아니다.
429·다른 오류·미확정 응답이 생기면 해당 stage를 중단하여 보존하며,
STOP을 자동 해제하거나 요청을 자동 재전송하지 않는다.

## 제한 원인 판단

공식 사용량 문서, CLI 소스와 공개 이슈를 함께 확인한다. API용 RPM/TPM을
ChatGPT 로그인 Codex의 보장 한계로 적용하지 않는다. 이 Cloud 환경은
네트워크 프록시를 거치며 프록시 자체의 429도 가능하지만, 현재 네트워크
진단 이력은 없어 원인으로 확정할 수 없다. 주간 사용량 잔여는 다른 단기
제한이 없다는 증거가 아니다. 모델 서버 전체 처리 능력과 현재 계정·모델·경로의
허용량을 구별한다. 기존 freeze와 본실험 배정은 이 조사에서 바꾸지 않는다.
