# Astra 중단 보존 및 10병렬 재개 기록

2026-11-07. 사용자의 “계속해” 지시에 따라 현재 VM의 10병렬 기술 검증과 본실험 재개를 진행한다. 이 문서는 실행 전 복구 계획이며, 검증 성공이나 재개 완료를 뜻하지 않는다.

## 현재 근거

- 본실험 83개 대화 완료, 3개 중단, 현재 배치에서 4개 미시작. 기존 2,863개 호출 예약 중 실제 응답 2,860개가 기록되어 있다.
- 이 VM의 Astra 단일 인증 확인 호출은 성공했다. 별도 운영 점검 1회이며 본실험·기술 검증 데이터에 포함하지 않는다. 다른 VM의 인증 상태는 확인되지 않았다.
- 중단된 세 대화와 기존 공개 결과는 그대로 보존한다. 기존 배치의 상태·저널·원시 디렉터리·823개 예산 티켓을 대조해 네 배정이 한 번도 시작되지 않았음을 확인했다.
- 기존 배치 원본은 비공개 로그 레포에 별도 중단 시점 스냅샷으로 검증·백업했다.

## 실행 순서

1. 원본 파일 해시를 묶은 복구 계획과 세 중단 상태의 보존 확인서를 만든다.
2. 현황판의 중단 사유·시각·실험 식별자·각 VM 예약 상태가 검토 당시와 같은 경우에만, 사용자 지시에 따른 공유 중단 해제를 한 번 기록한다. 공유 해제는 다른 VM에도 적용된다. 새로운 중단 신호는 자동 해제하지 않는다.
3. 종료된 이전 실행기의 잠금과 보존 확인서를 검사한 후 이 VM을 10병렬로 설정한다.
4. 새 기술 검증 `c10-01`에서 별도 대화 18개·612호출, 오류 여부와 실제 요청 시간 구간의 최대 동시성 10을 확인한다.
5. 통과하면 배치 `model-04-job-0003`의 미시작 배정 `main-030537`, `main-029898`, `main-038103`, `main-035551`만 최대 3병렬로 실행한다. 추가 호출은 최대 136회이며 원래 배치 예산 1,020회 이내다.
6. 기존 공개 결과를 덮어쓰지 않고 별도 revision을 게시한다. 네 대화가 모두 성공하면 해당 배치는 27 완료·3 중단·0 미시작, 총 959개 호출 예약으로 종료한다.
7. 미래 배치에 걸어 둔 운영용 보류만 해제한 뒤 본실험을 10병렬로 재개한다. 중단된 세 대화의 재시도·대체 표본 추가는 하지 않는다.

`exp7_ops_v1/recovery.py`와 명시적 보존 확인서를 받는 운영 도구만 추가했다. 사전 동결된 실험 코드, 배정, 프롬프트, 호출 상한은 변경하지 않았다. 복구·동시성 조정·측정·스냅샷 테스트 42개 및 동결 파일 검증을 통과했다.
