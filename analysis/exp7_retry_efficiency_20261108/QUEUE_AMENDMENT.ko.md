# 로컬 입장 대기줄의 불공정 발견과 마지막 FIFO 검증

v3의 두 설정을 완결·감사·백업한 뒤 지연을 분해했다. 6/100과 10/100의
실제 HTTP 왕복 p95는 약 4.47, 4.75초였으나 전체 논리 턴 p95는 6.47,
13.85초였다. 외부 응답 지연에 비해 로컬 대기가 크게 늘었다.

같은 본문 해시의 외부 중계 구간에서 물리 HTTP 처리 시간과 명시적 재시도
대기를 빼면, 입장 대기의 p95는 약 3.37, 10.66초이고 최대는 8.37,
31.65초였다. 이 분해는 근사치이며 RPC·서버 내부 계산 시간을 직접 분리한 것은 아니다.
소스의 대기줄이 선착순을 보장하지 않아, 뒤에 도착한 작업이 먼저 자리를 얻을 수 있었다.
10병렬의 긴 p95를 전부 서버 지연으로 해석할 수 없다.

## 수정과 검증

입장 순번을 부여하고 **선착순 FIFO**로만 전송을 허용한다. 요청 간격,
공통 cooldown, 재시도 예산·분류, 압축 요청 바이트, 과학 프로토콜은 유지한다.
STOP을 본 대기 항목은 전송하지 않고 줄에서 제거한다. 줄 도착·입장 순번과
대기 시간을 기록한다. 기존 v2/v3 소스·결과·선택 결정은 변경하지 않는다.

오프라인의 실제 CLI 34턴·압축·오류 검증 외에, 10개 작업의 도착/입장 순서와
STOP 뒤 대기 항목 제거를 검증한다. 이후 **마지막 실모델 점검 한 번**을 수행한다.

- 범위: `equivoque-2026-11-08-exp7-retry-efficiency-v4-fifo`.
- 새 위치: `/workspace/work/exp7-retry-efficiency-20261108-v4-fifo`.
- 10병렬·100회/분 시작 상한·FIFO, 새 30대화/1,020턴, 두 모델 각 15개.
- 물리 예산 1,320회, 새 입장 마감 900초. 다른 오류·STOP·미확정 요청 정책은 같다.
- 같은 frozen 시작 설정·프롬프트·스키마·effort·질문 순서와 기존 CLI 0.167.0을 사용한다.
- 원본 RPC·과학 프로토콜·같은 바이트 재시도·공통 대기·FIFO 순서를 감사하고 비공개 백업한다.

FIFO는 불필요한 순서 역전·기아를 없애기 위한 구현 수정으로 채택한다.
병렬 수는 새 10/FIFO의 전체 성공 속도가 이전 6/100보다 5% 이상 빠르고,
p95가 이전 10/100보다 낮으며 전체 완결·감사·백업이 통과할 때만 10으로 올린다.
그렇지 않으면 6을 유지한다. 이 경우 6/FIFO 자체의 실모델 처리량을
직접 측정했다고 표현하지 않는다. 새 소스는 다음 본수집 프로필에 동결해야 한다.

이 후속 검증도 운영 계측 문제를 발견한 뒤 추가한 탐색적 점검이다.
pool 변경과 FIFO 수정의 결합 전략을 비교하며, 순수 pool 효과를 주장하지 않는다.
이미 실패·미확정인 과학 시행의 대체가 아니다. 모든 이전 결과를 함께 보고하고,
이 한 번 이후에는 추가 실모델 점검을 반복해 유리한 결과를 찾지 않는다.
