# 실험 7: 0–100 카드 실험 준비안

**상태: 오프라인 준비 및 테스트. 본 수집 미시작.** 이전 실험 7 카드 계획 중
1–100 척도와 실험 5 활용에 관한 내용은 이 새 실행에 적용하지 않는다. 실험 5와
이전 1–100 실험 7 대화는 본 분석의 학습·조정·검증·직접 비교에 사용하지 않는다.
기존 자료는 보존한다. 새 실행 ID와 배정 시드 및 시행 ID를 사용한다.

## 연구질문과 설계

모델과 추론 수준, obj/seq 조건에 따라 자유도·영향력 보고 및 반사실 답변이
언제 어떻게 변하는지 관찰하고, K/D 예측과 결과 반복을 이용한 후보 모델이
그 변화를 설명하고 예측하는지 평가한다. 모델 응답은 관찰 가능한 보고이며,
이 자체로 주관적 경험이나 인간의 뇌 신호가 입증되는 것은 아니다.

- 7개 모델 × 3개 추론 수준 × obj/seq × 200시행 = 8,400개 독립 대화.
- 카드·영어·JSON 정수 응답. 자유도와 영향력은 **0–100**, 반사실은 yes/no.
  Pailhès, Kumari & Kuhn (2021)의 0–100 양 끝점과 일치시키되, 질문·절차 전체가
  원 논문과 동일한 복제는 아니다.
- 한 시행은 새 CLI 프로세스 및 하나의 대화에서 10라운드와 후속 질문을 마치며,
  완료 시 34턴이다. 목표 285,600턴에는 재시도가 포함되지 않는다.
- obj는 매 라운드 목표가 같고 seq는 네 목표가 각 2~3회 나오게 균형을 맞춘다.
  seq는 독립적인 균등 추첨이 아니므로 결과 반복에 1/4ⁿ을 자동 적용하지 않는다.
- 조합별 200개 중 160 case family는 모델 개발, 40개는 보류 검증에 사용한다.
  같은 family가 다른 모델·조건에서 반복되므로 분석에서 의존성을 고려한다.
  고정 목표 obj의 보류 표본은 새로운 목표 종류에 대한 검증이 아니다.

## 분석 초안: 수집 전 확정 필요

1. 매 라운드의 자유도·영향력 점수와 반사실 응답을 모두 보존하고 각 궤적 및
   기준 라운드 대비 첫 변화 시점을 보고한다. 첫 변화 자체를 붕괴로 단정하지 않는다.
2. 이전 계획의 공동 사건을 0–100에 맞춘 후보 지표는 `impact=0`과
   `counterfactual=no`가 처음 함께 나타난 라운드다. 이는 영향이 없다고 보고한
   조작적 지표로, 모든 가능한 전환을 대표하거나 실제 SoA 붕괴를 입증하지 않는다.
   10라운드 내 사건이 없으면 해당 시점에 중도절단하고 결측·오류와 구분한다.
   기준·방향·첫 변화의 정확한 정의는 본 수집 전 고정해야 한다.
3. 10라운드 후 규칙 예측과 설명을 따로 평가한다. 자기 보고의 변화와 규칙을
   알아맞히는 능력은 다른 변수이며 후속 질문이 통찰을 유도할 수 있다.
4. 라운드 기준선과 K/D 베타-마르코프 놀람값, 결과 반복 및 결합 모델을 비교한다.
   K/D 각 전이의 초기 분포는 Beta(1,1)이며 K/D 두 선택씩을 끊지 않고 전체
   시간순으로 계산한다. 특징량은 관찰되는 보고 이전에 알 수 있는 정보만 쓴다.
   누적 놀람값은 관찰 자료의 계산값이지 LLM의 실제 내부 믿음이 아니다.
   모델 선정·조정은 새 실험의 개발 표본만 사용하고 보류 표본으로 평가한다.
   임계형이 점진형보다 나은지는 데이터와 모델 회복 검증에 달려 있다.

언어·출력 형식의 영향, 고정/변동 규칙의 별도 대조는 이 카드·영어·JSON
obj/seq 설계만으로 검증하지 못한다. 200이라는 표본 수 자체가 충분한 검정력이나
안정적인 임계값을 보장하지 않는다.

## 구현과 남은 일

정제된 전체 질문과 예시는 [프롬프트 원문](PROMPTS.ko.md)을 참고한다. 게임
문장에서 반복적인 JSON 안내를 빼고, 결과를 “Your chosen card” 대신 “The
remaining card”라고 제시한다. 영향력의 100점 기준은 기존 “complete control”에서
“extreme impact”로 변경했다. 이 기준점 변경은 측정 문구의 실질적인 변화다.
스키마는 별도로 전송되며 첫 선택 키는 `cards`, 두 번째는 `card`다. 시스템
문장에서도 JSON 지시와 대화 정보만 사용하라는 지시를 제거했다. 이 CLI는 빈
시스템 지시 파일을 거부하므로 행동 지시가 아닌 마침표 하나를 전달한다. CLI가
환경 정보를 추가하며 도구는 비활성화된 기술 점검 환경이다. 예측 질문에서 출력
코드 이름을 직접 언급하지 않으며 답변 스키마에는 남아 있다.
후속 질문에서도 “분석하지 말라”와 “관찰한 라운드만 바탕으로”라는 제한을
제거했다. 해당 후속 질문은 기존 42개 기술 점검 후 바뀌어 다시 검증해야 한다.

이전 버전(시스템 문장에 대화 정보만 사용하라는 지시가 있던 버전)의 2026-11-18
별도 기술 점검에서 gpt-5.6-luna/low, obj 대화 한 개를 실제 CLI의
한 프로세스·세션으로 실행했다. 34턴 전체가 스키마에 맞았고 기록 무결성 검사를
통과했으며 기록상 압축 이벤트는 0건이었다. 이 대화는 본 표본이 아니다. 한 모델의
점검 결과이므로 나머지 모델·추론 수준과 서비스 조건 전체에 일반화하지 않는다.

`protocol.py`는 질문, JSON 스키마, 파싱의 세 곳에서 0을 허용한다.
`features.py`는 공동 사건 지표에서 0을 허용한다. `schedule.py`는 다른 실행 ID,
시드, 시행 ID를 가진 8,400개 배정을 오프라인으로 만든다. 과거 프로토콜은
고치지 않았다. 테스트는 가짜 응답으로 양 조건을 34턴 완주하고 척도 양 끝점,
범위 밖 입력, 배정 수와 공동 사건을 확인한다.

```bash
python -m unittest -v exp7_cards_zero.test_zero
python -m exp7_cards_zero.schedule --output /tmp/exp7-zero-manifest
```

**아직 실제 수집에 연결되지 않았다.** 기존 1–100 worker·현황판을 그대로 실행하면
새 프로토콜이 적용되지 않는다. 새 배정과 프로토콜을 재시도 실행기 및 독립
현황판에 연결하고, 실제 CLI 세션·컨텍스트/압축·모델별 가용성·기록/실패 처리와
새 척도를 검증해야 한다. 분석 및 표본 수 계획도 수집 전에 고정해야 한다.
오프라인 테스트는 실제 서비스의 속도나 컨텍스트 용량을 증명하지 않는다.
