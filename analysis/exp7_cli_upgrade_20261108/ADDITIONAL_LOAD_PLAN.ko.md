# 모델 분산에 따른 부하 점검

버전 간 비교는 SQLite 분리 조건의 기존 → 안정판 → 시험판 → 안정판 →
기존 순서를 마친다. 각 block은 2모델 medium, pool 4, 80회/분 입장 상한,
새로운 대화 4개이다. 성능 승자를 사후 선택하지 않고 부하 확대에는 안정판
0.167.0을 사용한다. 시험판은 안정판과 차이를 설명하는 비교 대상으로 남긴다.

통과한 경우 다음 순서로 각자 별도 stage에서 점검한다.

1. 안정판, 기존 두 모델, pool 6, 100회/분 상한, 6대화.
2. 안정판, 원래 설계의 8모델 모두 medium, pool 8, 160회/분 상한,
   모델마다 새 대화 1개씩 총 8대화. 모델별 동시 대화 수는 1이다.
3. 안정판, 기존 두 모델, pool 8, 110회/분 상한, 8대화.
   이전 CLI의 같은 부하 실패 기록과 비교하되 시간대 차이에 따른 한계를 명시한다.

어느 stage든 실제 429나 다른 오류가 발생하면 해당 stage를 중단하고
원본·pending을 보존한다. 이후의 부하 확대를 자동 실행하지 않는다.
모델·effort·조건을 바꾼 임의의 성공 시행으로 실패를 대체하지 않는다.
사용자가 요청한 본실험 전체 표본 및 기존 STOP은 이 기술점검에서 바꾸지 않는다.

관측 중인 것은 이 계정/경로/모델들의 유한한 부하에 대한 성공 여부이다.
8모델 분산이 통과하더라도 모든 추론 수준에서 같은 속도 또는 장시간 안정성을
보장하지 않는다. 두 모델의 110회/분 실패를 전체 모델의 고정 계정 한계로
일반화하지 않는다. 실제 rolling 60초 입장 수, 관측 RPC 중첩과 p95를 함께 보고한다.
