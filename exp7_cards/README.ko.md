# 실험 7 카드 전용 obj/seq — 수집 전 준비안

**상태: 오프라인 준비. 실제 수집 준비 완료나 실행 승인을 뜻하지 않는다.**
기존 실험 5를 탐색 자료로 사용하고, 새 독립 대화에서 응답 전환의 확률을 예측한다.
이 브랜치의 배정·테스트는 모델을 호출하지 않는다. 과거 본실험과 그 STOP,
동결 파일, 실행 기록을 수정하거나 재개하지 않는다.

## 설계와 배정

- 일곱 모델 × low/medium/high × obj/seq, **42개 조합**.
- 각 조합에 200개 새 대화, 총 **8,400개 대화 / 최대 84,000라운드**.
- 소재는 카드, 영어, JSON schema, 매 라운드 선택 자유·영향력·반사실 질문.
- 대화 하나는 신규 CLI 세션에서 연속 10라운드. 후속 질문 4개까지 완주하면
  34호출, 전체 계획 최대 285,600호출이다. 기술점검·실패·재시도는 별도 계수한다.
- obj는 한 카드가 10회 목표. seq는 4개 카드가 각각 2~3회 나타나도록 사전 생성한
  서로 다른 200개 시퀀스다. 같은 case의 obj/seq 첫 목표와 카드 배열을 맞춘다.
  obj의 네 목표는 조합당 각 50개다. 전체적으로 24개 카드 배열을 8~9회씩 사용한다.
- 원래 계획과 달리 여러 seq를 사용한다. 균형 제약이 있는 생성이므로 실제 배정은
  라운드별 독립 균등 `1/4` 추첨이 아니다. 이 배정의 반복 확률에 `1/4^n`을
  자동 적용하지 않는다. 카드 순서와 목표 시퀀스는 참여 모델에게 사전 고지하지 않는다.
- 200개 case family를 모든 모델·조건에서 공유한다. 160개 family는 개발용,
  40개는 보류 검증용이며 개발 family는 5개 fold에 각 32개씩 배정한다.
  검증용 seq는 개발에 등장하지 않은 시퀀스지만, obj는 네 고정 목표를 모든
  분할에서 반복한다. 따라서 obj 검증은 새로운 목표 종류에 대한 검증이 아니다.
- 조합당 처음 50개는 실행 가능성 점검분이고 150개는 이후 수집분이다. 각
  점검분에는 개발 40, 보류 10 family가 있다. 보류 결과는 모델 선택에 쓰지 않는다.
  여기에 정한 200개는 통계적 검정력 보증이 아니라 계획 예산이다.
- 각 조합의 마지막 후속 질문은 explanation/neutral 각각 100개로 배정한다.
  자유서술·경로 예측·공개 후 질문은 10라운드 측정 이후에만 실시한다. 질문은
  새로운 추론을 유발할 수 있으므로 그 답을 기존의 자발적 발견 시점과 혼동하지 않는다.

## 관측 및 분석 계약 초안

주요 사건은 라운드에서 **`impact=1`과 `counterfactual=no`가 처음 함께 보고됨**.
개별 영향력 점수, 반사실·자유도, 이후 복귀도 따로 보존한다. 주된 시간 분석은
사건이 없었던 대화를 10라운드에서 중도절단으로 처리한다. 파싱 불가·실패와
전환 없음을 구분하고, 할당 수·완주 수·관측 수를 함께 보고한다. 이 응답은
모델의 주관적 경험을 직접 측정하지 않는다.

전환 전까지 매 라운드의 선택과 피드백을 본 직후, 해당 라운드 첫 공동 보고의
조건부 확률을 예측한다. 보고된 응답을 예측 입력에 넣지 않는다. 후보:

1. 라운드만 사용하는 기준선.
2. 기존 실험 5 분석의 시간순 K/D 베타-마르코프 예측: 직전 K와 D 각각
   Beta(1,1)에서 시작해 예측 후 갱신하고 surprisal을 계산한다. 라운드 사이
   초기화하지 않는다. 첫 관측은 앵커다.
3. 결과 반복 정보. 계산 시점까지 관찰한 결과만 쓴다. 확률에 사용하는
   가상 생성 가정은 실제 균형 배정과 구분해 명시한다.
4. K/D와 반복 정보를 함께 사용하는 모델. 동일 피드백과 결과가 종속적이므로
   서로 독립인 증거로 곱하지 않는다.

모든 후보는 라운드를 통제하거나 라운드 기준선과 비교한다. 개발 family에서만
모형과 하이퍼파라미터를 정하고 완전히 분리된 보류 family에서 로그 손실,
브리어 점수, 예측 확률과 관측 비율의 일치를 보고한다. 대화·case family의
의존성을 고려해 불확실성을 추정한다. 드문 seq 사건에서 조합별 모델 또는
임계값을 안정적으로 추정할 수 없다면 불가로 보고한다. 임계형과 점진형의
비교는 데이터가 식별 가능한지 시뮬레이션을 거친 후 시행한다. 누적 surprisal은
시간과 함께 증가할 수 있으며 단독으로 심리적 손상이나 실측 믿음을 뜻하지 않는다.

**분석 구현·사전등록은 아직 완성되지 않았다.** 라운드별 결측 처리, 사용할 모델의
정확한 식·사전분포와 단순 모델의 자유도, 시뮬레이션 기반 모델 회복 및 표본 수
검토를 수집 전 확정해야 한다. obj/seq만으로 규칙 변동과 결과 반복의 순수한
효과를 분리할 수 없다. 고정 K/D·변동 규칙 대조, 언어·형식·프레임 검증은 별도다.

`features.py`는 완성 또는 중단된 runner state에서 첫 공동 보고까지의 라운드별
위험집합, K/D surprisal과 같은 결과의 연속 길이를 만드는 오프라인 초안이다.
판독할 수 없는 라운드는 최초 사건의 관측을 끊으며 0으로 바꾸지 않는다. 이
함수는 통계 모델을 적합하거나 모델 간 우열을 검정하지 않는다.

## 재현 및 오프라인 점검

저장소 루트에서:

```bash
python -m exp7_cards.schedule --output /tmp/exp7-cards-manifest-check
python -m unittest -v exp7_cards.test_preparation
```

`manifest/schedule.json`, `assignments.jsonl.gz`, `jobs.json`, `audit.json`은 같은
명령으로 만든 초안 배정 묶음이다. 280개 30대화 작업 중 70개가 첫 점검 단계다.
다른 기존 파일을 덮어쓰지 않는다. 작업 묶음은 아직 기존 분산 worker에 연결되지
않았고 `exp7_main_v2`의 기존 audit은 77,856개 단일 시퀀스 설계를 강제한다.
그 worker에 이 파일을 그대로 주어 실제 실행해서는 안 된다.

`CardProtocol`은 기존 `PreProtocol`의 영어/schema 표현과 파서를 사용하되,
고정 배열만 허용하는 이전 main 검증 대신 카드 순서 변경을 검증한다. 테스트는
기존 main과 기본 배열 프롬프트/schema가 같은지 확인하고 obj/seq 각 하나를
가짜 응답으로 34턴 실행해 한 세션, 목표 결과와 라운드를 점검한다. 실제 모델
호출·실제 CLI 연결·실제 context 압축 여부를 검증한 것은 아니다.

## 수집 전 남은 구현·확인

1. 새 배정용 worker·작업판 및 정확한 freeze/해시를 만들고 기존 worker의 77,856개
   전용 가정을 새 설계에 안전하게 적용한다. 여러 VM 전역 호출 제한과 중단,
   미확정 요청의 보존을 실제 환경에서 확인한다. 실패 대화는 자동 재생하지 않는다.
2. 각 모델/추론 수준의 실제 접근, 10라운드 동일 세션과 최초 context 한도,
   압축 감지 가능 여부를 별도 기술 대화로 확인한다. 압축/검증 불가를 표시하고
   주 분석 편입 규칙을 사전에 정한다. 기술 대화는 본 표본에 넣지 않는다.
3. native 원본·토큰·오류와 429 재시도 관측, 비공개 내구 저장과 복원 검증,
   모델별 사용량·예산을 확인한다. 과거의 측정값은 현재 속도를 보장하지 않는다.
4. 위 분석 계약과 시뮬레이션을 구현하고, 초기 50개 점검에서 볼 항목과 추후
   150개에 대한 운영 결정을 사전에 기록한다. 보류 결과를 모델 선택에 쓰지 않는다.
