# 실험 7 저장 위험과 v2 개선

2026-11-07. 본실험 시작 직전 사용자의 원본 로그·DB 용량 우려를 점검했다. v1은 코드와 작업판만 게시했고 본실험·기술 대화는0개다. 원본을 누적하는 방식의 위험을 확인해, 동일한 과학 설계에 저장·배포 개선을 적용한 v2로 진행한다. 기존 원본과 v1 동결 파일은 변경하지 않았다.

## 실측과 예상 규모

7-pre 1,200대화의 원시 기록을 읽고 파일 크기·할당량을 확인했다. 결과와 무관하게 모델·추론×팔×게임의 첫 배정96개를 선택해12,276개 원본 파일을 임시 압축했고, 다시 열어 모든 SHA256을 확인했다. 원본을 실제 삭제·수정하지 않았다.

| 항목 | 실측 |
|---|---:|
| 상태 JSON | 278.44 MB |
| 요청·응답 journal | 230.91 MB |
| native 파일 내용 | 81.65 MB |
| native 파일의 디스크 할당 | 522.34 MB |
| native 디렉터리의 디스크 할당 | 168.30 MB |
| 위 상태·journal·native 전체 할당 | 1.211 GB |

작은 파일은 내용보다 큰 디스크 블록을 차지하고, 빈 파일도 inode를 소비한다. 34번의 호출마다 prompt·events·stderr와 선택적으로 schema 파일이 생긴다. 원본과 상태·journal에는 일부 내용이 반복된다.

최신 계획의 한 모델9,732대화에는 schema5,412개와 자연어4,320개가 있다. 모두 완주하면 native 파일1,186,404개, native 디렉터리340,620개, 상태·journal·lock29,196개, 별도 대화 폴더19,464개가 생긴다. CLI rollout까지 포함하면 **약159만 항목**이며 Git·임시 파일은 추가다. 감사 시점 이 VM의 남은 inode는 약187만 개였으므로 여유가 좁다. 8모델을 한 VM에 펼쳐 취합하면 약1,270만 항목으로 이 한도를 넘는다.

## 압축 측정

| 96개 대표 대화 자료 | 압축 전 내용 | 압축 후 |
|---|---:|---:|
| 원본 상태·journal·native | 46.39 MB | 2.707 MB |
| 공개용 연구 JSONL | 7.432 MB | 0.696 MB |

현 계획의 형식 비율과34호출로 환산하면 **모델당 원본 압축 약285 MB, 공개용 gzip 약82 MB**라는 참고값이 나온다. 펼쳐진 원본은 파일 할당 약8.05 GB, native 디렉터리까지 약9.44 GB다. 압축 색인, CLI 자체 저장, Git, 기술 점검, 실패·백업은 이 수치에 추가한다.

이는 미래 용량 상한이 아니다. 한국어 자연어는 pre의 영어 자연어 F를 대용했고, 신규 모델·추론·고양이 프레임·출력 길이의 변화가 남는다. 압축 파일만 추가하고 펼친 원본을 그대로 두면 공간이 줄지 않는다.

Codex 자체 저장소도 별도다. 과거 실험의 정확한1,200개 세션 ID에 대응하는 rollout 파일은354.81 MB였고, 같은 비율이면 모델당 약2.88 GB다. 공용 thread-history SQLite는 약126.63 MB지만 다른 작업도 포함한다. 따라서 이 DB를 실험 데이터만 있는 저장소로 취급하거나 임의로 삭제하지 않는다. 메타데이터·행 수·내용 길이만 조사했으며 인증 내용이나 다른 대화 내용을 읽지 않았다.

## 적용한 개선

1. **완료 작업을 원본 그대로 압축한다.** 모델별30대화 작업의 공개 결과 업로드와 공통 작업판 완료 기록이 확인된 뒤, 자체 `states/`와 `native/`를 tar.gz와 파일별 SHA256 색인으로 만든다. 다시 열어 모든 바이트·크기를 검증한 후에만 펼친 파일을 정리한다. 원본 내용은 복원 가능하다.
2. **재실행·손실 방지 기록을 남긴다.** 선점·예산·공개 결과·압축 완료 증명은 남긴다. 압축한 대화가 미시작으로 취급되지 않는다. 중단·pending·잠긴 상태·알 수 없는 파일·심볼릭 링크·손상된 압축본은 정리를 차단한다. 중간에 정리가 끊겨도 검증된 아카이브로 복구한다.
3. **작업 공간의 최저 여유를 검사한다.** 작업/요청 경계에서 작업 디스크와 Codex 저장 디스크를 검사한다. 5 GiB 또는100,000 inode 아래면 새 호출을 멈춘다. 실행 중 검사는 최대60초 캐시이며 이미 전송한 요청을 소급 취소하지 않는다.
4. **Git의 누적 비용을 줄인다.** heartbeat를 최대1분에 한 번으로 제한한다. bare 캐시는 영구 tracking ref를 써서 증분 fetch하고 이력 후퇴를 거부한다. 미확정 push는 보호 ref에 남긴 채 안전하게 repack한다. raw 파일을 호출마다 Git에 넣지 않고, 공개 결과만 작업당 gzip 한 개로 게시한다.
5. **VM 배포를 작게 만든다.** 현재 전체 소스 트리에는 과거 기록까지356,861파일·약4.53 GB가 있다. 실제 v1 실행 의존성은60파일·약4.01 MB였고 압축은 약2.35 MB였다. v2도 동결된 실행 파일·배정만 담은 검증 가능한 소스 묶음으로 배포한다. 정확한 v2 크기는 release 자산에서 확인한다.
6. **분석은 압축 묶음 단위로 읽는다.** 전체 원본을 한 번에 메모리에 올리거나 다시 수백만 파일로 풀어 합치지 않는다. 후속 분석에서는 작업별 JSONL을 순차 읽고 대화·라운드별 작은 파생 표를 만든다. Parquet/DuckDB 같은 분석 저장 형식은 원본 보존과 별개로 도입할 수 있으며 이번 실행기의 필수 의존성으로 추가하지 않았다.

기술 점검18대화는 기존 무결성 확인에 필요한 펼친 원본을 유지한다. CLI 공용 DB·rollout은 자동 정리하지 않으며 해당 용량을 별도 예산에 포함한다. 현재 exec/resume은 세션 저장에 의존하므로 `--ephemeral`을 켜서 저장을 줄이지 않는다.

## 백업의 남은 범위

GitHub에는 프롬프트·모델 원문 답변·선택·피드백·판독·증거 해시가 담긴 연구 자료가 남는다. 인증·provider 세션 ID·로컬 경로·명령행·원시 진단 로그는 공개본에서 제외한다. 전체 native 증거와 상태 원본의 압축본·색인은 각 VM의 비공개 저장소에 남긴다.

**압축과 외부 백업은 다르다.** VM 디스크가 사라지면 공개 연구 자료는 남아도 비공개 원시 증거는 유실될 수 있다. 별도 원본 백업 저장소는 아직 설정하지 않았다. 원본의 영구 보존을 위해서는 검증된 아카이브·색인을 별도 지속 저장소로 복사하고 체크섬을 확인해야 한다. 이 한계를 숨기고 완전한 백업이 끝났다고 주장하지 않는다.
