# 사용자 승인 범위의 헤더 진단

2026-11-08 사용자 요청: “헤더확인하는 테스트해봐 그리고 분석”.

기존 본실험 STOP과 이전 기술점검 HALT는 유지한다. 아래는 새 실행 ID의
별도 진단이며, 미확정 시행을 재개하거나 성공 시행으로 대체하지 않는다.
기존 freeze·결과·원본은 변경하지 않는다.

## 방식

- 검증된 별도 CLI 0.167.0, 기존 native 인증 home 사용. 인증 파일·토큰을
  다른 home으로 복사하거나 CLI 인자로 추출하지 않는다.
- 지원되는 custom provider 설정으로 HTTP/SSE와 request/stream 재시도 0을
  명시한다. 로컬 중계기는 127.0.0.1에만 바인딩한다.
- native CLI가 보낸 인증은 메모리에서 고정된 공식
  `https://chatgpt.com/backend-api/codex/responses`로만 전달한다.
  기존 환경 프록시·CA와 TLS 검증을 유지하고, redirect를 따르지 않는다.
- 요청 본문·요청 헤더는 중계 로그에 쓰지 않는다. 요청은 hash/byte count만
  남기며, 응답의 제한·대기·request ID·경로 관련 허용된 헤더와 오류 본문을 기록한다.
  쿠키·인증·잔액은 제외한다. 오류가 인증값을 반사하면 저장/전달하지 않는다.
- 기본 WebSocket 경로와 달리 HTTP/SSE인 점을 결과에 명시한다. 이것은
  응답 헤더 진단이며 기존 모델 응답 분포와 동등하다는 검증이 아니다.

## 순서와 중단

1. 실제 CLI와 로컬 가짜 서버에서 정상 SSE, 429 1회 후 재전송 없음,
   헤더/본문 기록 및 인증값 누출 방지를 검증한다. 외부 모델 호출은 0이다.
2. Canary: Astra와 5.6 Sol medium 각 1턴, 순차 실행, 최대 upstream 요청 2회.
   기존 실험의 첫 질문·스키마·시스템 지침을 사용한다.
3. Canary가 통과하고 필요한 오류가 아직 안 잡힌 경우에만 별도 load 진단:
   두 모델 medium, 최대 8개 독립 대화, 원래 34턴 질문 순서, upstream 요청
   총 144회 상한과 입장 간격 0.375초. budget에 도달하면 그대로 중단한다.

첫 HTTP 오류 또는 스트리밍 오류를 관측하면 새 upstream 입장을 차단한다.
이미 진행 중인 요청의 결과·미확정 상태를 보존하며 자동 재전송하지 않는다.
로컬 입장 차단의 503은 upstream 429와 구별한다. 새 STOP을 자동 해제하지 않는다.

목표는 정확한 error.type/code/message, Retry-After, rate-limit 헤더와
upstream request ID를 확보하는 것이다. 숫자 한도가 없으면 미공개라고 기록하고
단일 진단으로 고정 RPM이나 전체 서버 용량을 추정하지 않는다.
