# 추가 기술점검 없이 3병렬 계속 실행

2026-11-07 사용자가 “기술점검은 하지말고 그냥 재개”를 명시했다. 추가 calibration, 인증 확인용 생성 호출, 용량 시험 없이 원래 CLI·3병렬로 본실험을 재개했다. 공통 STOP은 이미 해제되어 있었다.

직전 4번 작업은 외부 공통 STOP에 따라 3개 중단·27개 미시작, 66개 호출 예약·63개 정상 응답으로 종료됐다. 원래 세 중단 상태와 체크포인트, 공개 결과를 그대로 보존하고, 한 번도 시작되지 않은 원래 27개 배정만 이어서 실행한다. 원래 호출 상한 1,020회를 유지하며 추가 허용량은 918회다.

운영 실행기는 `exp7_ops_v1.resume_unstarted`다. 이전 자료를 비삭제 압축·비공개 레포 백업 후 27개를 최대 3병렬로 수행한다. 결과는 별도 revision으로 게시하고 새 원시 자료도 백업한다. 정상적으로 배치를 마치면 기존 frozen 실행기의 `run` 명령으로 다음 배정을 계속 가져온다. `prepare`나 새 기술점검은 호출하지 않는다. 기존에 통과한 readiness 기록을 읽는 동작은 새 모델 호출을 만들지 않는다.

15:45 UTC에 실행을 시작했으며, 확인 시점에 3개 대화가 active이고 새 응답 9개가 정상 반환됐다. 본실험 완료 누적은 현재 87개이며, 기존 중단 6개는 보존한다. 동결된 실험 코드·프롬프트·배정은 변경하지 않았다. 운영 도구의 임의 개수 미시작 배정 지원은 기존 4개와 새 27개를 포함한 오프라인 테스트 9개를 통과했다. 이는 추가 모델 기술점검이 아니다.

[GitHub 현황판](https://github.com/dasnidm/llm-equivoque-experiments/tree/exp7/main-v2-coordination). 대화 완료 집계는 작업 결과 게시 시 갱신된다. 이후 새로운 공통 STOP이 발생하면 원본을 보존하며 중단하고, 임의로 반복 해제하지 않는다.
