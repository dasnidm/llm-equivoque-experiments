# 실험 7 실행 방식 전환 기록

기존 실행 `equivoque-2026-11-07-exp7-main-v2`는 실행 방식 전환 전 수집분으로 보존한다. 예비실험으로 사후 재분류하지 않는다. 기존 공통 현황판 `exp7/main-v2-coordination`은 중지 상태로 유지하며, 기존 결과·원본·실패 및 불확실 요청·manifest·freeze를 변경하거나 삭제하지 않는다. 원본 백업은 비공개 `dasnidm/llm-equivoque-exp7-raw`의 기존 실행 네임스페이스에 보존한다.

기존 방식은 매 턴 `codex exec` 또는 `codex exec resume` 프로세스를 새로 실행했다. 새 방식은 한 독립 시행의 10라운드와 후속 질문을 하나의 `codex app-server` 프로세스와 동일한 새 대화에서 수행한다. 기존 대화를 이어받지 않는다. 오프라인 검증은 실제 모델의 응답 분포 동등성을 증명하지 못한다. 따라서 기존 수집분 전체와 새 실행 `equivoque-2026-11-08-exp7-persistent-v1`의 본실험 주 분석은 합치지 않는다. 이 구분은 응답 내용이나 성적을 보고 선택한 것이 아니라 실행 조건의 변경에 따른 전체 수집분 분리다. 별도 기술점검도 본실험 표본에 포함하지 않는다.

새 배정 77,856개와 기존 배정의 시행 ID 및 모든 필드가 실행 ID를 제외하고 동일함을 확인했다. 난수 시드 `2026110707`과 2,600개 작업 배정도 동일하다. 명시적 대응표와 기계 검증 결과는 새 manifest 디렉터리에 보관한다. 프롬프트 및 프로토콜 관련 핵심 파일의 해시는 기존 freeze와 일치한다. 원래 설계 전체를 새 실행에서 처음부터 수집하며, 기존 실패나 불확실 시행을 임의로 대체하지 않는다.

소스 기준 커밋은 `9171e0612ad50fa8e2d999ba0af212cf37291a60`, CLI는 `codex-cli 0.159.0-alpha.3`, 전송 방식은 `persistent`, 각 VM 내 요청 시작 최소 간격은 1초다. 이 간격은 계정 전체 제한이 아니다. 모델 목록은 새 manifest의 `model-catalog.json`에 고정한다. 새 공통 현황판과 결과·원본 백업 경로는 기존 실행과 분리한다. 병렬 수는 새 프로필에서 측정된 기술점검 결과에 따라 정하고 예약 수와 실제 pool 수를 일치시킨다. 새 STOP은 자동 해제하지 않는다.
